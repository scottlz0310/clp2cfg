## 1. winget-pkgs 審査で想定される論点と対応方針

### 1.1 スキーマ `1.28.0` への更新と `Validation-Guide` ラベル

- **背景**: `0.1.0` の申請マニフェスト（[microsoft/winget-pkgs#464302](https://github.com/microsoft/winget-pkgs/pull/464302)）は当初 `ManifestVersion: 1.9.0` で提出されていましたが、`microsoft/winget-pkgs` 側の推奨スキーマが `1.28.0`（許容下限 `1.12.0`）へ移行したため、先行して `1.28.0` スキーマおよび `PrivacyUrl` へ更新済みです（コミット `ba8eb8b9c`）。
- **注意点**: 万が一、過去状態へのバッチ検知等で `Validation-Guide` や `Manifest-Version-Deprecated` ラベルが付与された場合は、自動解除されないケースがあるため、既に `1.28.0` 適合済みである旨を PR にコメントして再確認を依頼します。
- **適用済みの変更点（`1.9.0` → `1.28.0`）**:
  - 各 YAML 先頭の `# yaml-language-server: $schema=...` と末尾の `ManifestVersion` を `1.28.0` に更新。
  - `locale.en-US.yaml` に `PrivacyUrl: https://scottlz0310.github.io/clp2cfg/privacy-policy.html` を追加。

`1.28.0` 更新後の報告コメント例:

```text
Updated the manifest schema to `1.28.0` as requested and added `PrivacyUrl`.
Verified locally with `winget validate --manifest <path>` (winget v1.29.380): `Manifest validation succeeded.`
Could a maintainer please review and remove the `Validation-Guide` label when convenient? Thank you!
```

### 1.2 Portable 形式特有の `DisplayVersion` 自動警告

- **現象**: `InstallerType: zip` + `NestedInstallerType: portable` のパッケージでは、YAML に `DisplayVersion` を記述していなくても、検証パイプラインが生成した仮想 ARP（Add/Remove Programs）エントリに対して「`DisplayVersion` と `PackageVersion` が同じなので削除推奨」という旨の警告が出ることがあります。
- **対処**: YAML に `DisplayVersion` を書いていない場合はツール側の挙動による見かけ上の警告です。無意味な修正を繰り返さず、そのまま事実のみを説明します。

指摘・確認が入った場合の説明コメント例:

```text
Note on the `DisplayVersion` warning: `DisplayVersion` is not specified in any of the submitted YAML files (this is a `zip` + `portable` manifest). It appears the check flagged the synthetic ARP entry generated by WinGet during validation.
```

### 1.3 未署名バイナリ・Windows Defender スキャン・サンドボックス最終確認

- **未署名バイナリの扱い**: 個人開発のためコード署名証明書による Authenticode 署名は付与していません。未署名であっても、未署名である旨と公開アセットに対する Windows Defender スキャン結果を明記することで審査を通過できます。
- **サンドボックスでの実機確認との整合**: 最終承認前にメンテナが検証環境（Windows Sandbox 等）で実アプリを起動し、ローカル通信の有無や基本挙動を確認する場合があります。
  - `clp2cfg` 本体自身はネットワーク通信を行う実装（`std::net` / HTTP クライアント等）を持たず、スニペット解析は端末内のメモリ上のみで処理します（起動直後・待機状態の TCP/UDP 接続も 0 件です）。
  - ファイル系ターゲット（Claude Code / Desktop、Cursor、VS Code Copilot、Project Local `.mcp.json`、Windsurf、Cline、Roo Code、Zed）への適用では、ローカル設定ファイルへ `.bak` バックアップ付きで書き込みます。
  - ユーザーが CLI 委譲ターゲット（`claude-cli` / `codex-cli` / `copilot-cli` / `antigravity-cli`）を明示選択して適用したときのみ、ローカルにインストールされた公式 CLI（`claude` / `codex` / `copilot` / `agy`）をサブプロセスとして実行します。この経路は `clp2cfg` によるファイル直接書き込み・`.bak` バックアップは通らず、委譲先の外部 CLI 自体が行う通信やデータ処理には各ツール提供元のプライバシーポリシーが適用されます。
  - 上記の挙動は [プライバシーポリシー](https://scottlz0310.github.io/clp2cfg/privacy-policy.html)（正本: [`docs/privacy-policy.md`](../../docs/privacy-policy.md)）およびマニフェストの説明文と一致しています。
- **PE バージョンリソースの補足**:
  - `v0.1.0` の `clp2cfg.exe` には PE の `FileVersion` / `ProductVersion` が未埋め込みです。
  - `v0.3.3` の `clp2cfg.exe` には `0.3.3` が埋め込まれています（`clp2cfg-cli.exe` は workspace 分割の既知制約により未埋め込み）。

PR 本文・コメントに添える未署名＋スキャン報告例:

```text
- The binaries are unsigned (personal open-source project without a code-signing certificate), which is documented in the repository README.
- Windows Defender (`MpCmdRun.exe -Scan -ScanType 3`) was run against the exact published release ZIP and extracted executables, reporting no threats.
- The clp2cfg executables themselves make no network connections (verified against the source code and idle runtime TCP/UDP checks). When applying to file-based targets, they only merge into local AI client config files with `.bak` backups; when a user explicitly selects a CLI delegation target (`claude-cli`, `codex-cli`, `copilot-cli`, or `antigravity-cli`), the app invokes that locally installed official CLI as a subprocess without `.bak` backups, and any network or data behavior of that external CLI is governed by its own provider policy.
```

## 2. ローカル事前検証手順（`0.1.0` を変更しない検証）

公開済みリリース ZIP の SHA-256 照合・未署名確認・Windows Defender スキャン・`1.28.0` マニフェストのローカル検証は、リポジトリ外の一時ディレクトリで実行できます。

```powershell
# 例: v0.3.3 を一時ディレクトリへ取得して照合・スキャンする
$tag = "v0.3.3"
$ver = $tag.TrimStart("v")
$tmp = Join-Path $env:TEMP "clp2cfg-winget-verify-$ver"
New-Item -ItemType Directory -Force -Path $tmp | Out-Null

gh release download $tag -R scottlz0310/clp2cfg -p "clp2cfg-x86_64-pc-windows-msvc.zip*" -D $tmp --clobber

$zip = Join-Path $tmp "clp2cfg-x86_64-pc-windows-msvc.zip"
$sha = [System.BitConverter]::ToString(
    [System.Security.Cryptography.SHA256]::Create().ComputeHash([System.IO.File]::ReadAllBytes($zip))
).Replace("-", "").ToLower()
Write-Output "ZIP SHA256: $sha"
Get-Content "$zip.sha256"

$dest = Join-Path $tmp "extracted"
if (Test-Path $dest) { Remove-Item $dest -Recurse -Force }
Add-Type -AssemblyName System.IO.Compression.FileSystem
[System.IO.Compression.ZipFile]::ExtractToDirectory($zip, $dest)

# Windows Defender スキャン
$mp = "$env:ProgramFiles\Windows Defender\MpCmdRun.exe"
& $mp -Scan -ScanType 3 -File $tmp
```

マニフェストディレクトリの検証は `winget validate` を使用します（対象ディレクトリはリポジトリ外の検証用フォルダを指定してください）。

```powershell
winget validate --manifest <path-to-manifest-dir>
```

## 4. 次期更新および自動更新パイプライン（Issue #38）向け設計方針

[#38](https://github.com/scottlz0310/clp2cfg/issues/38) は、`#464302` が `microsoft/winget-pkgs` へマージされた後に着手します。マージ後の更新と自動化では、次の 4 点を設計前提とします。

1. **スキーマ `1.28.0` と `PrivacyUrl` の維持**
   - 更新時のマニフェストは常に `ManifestVersion: 1.28.0` 以降と `PrivacyUrl: https://scottlz0310.github.io/clp2cfg/privacy-policy.html` を維持する。
2. **配布アセットの正規表現（`.zip` 明示）**
   - `clp2cfg` の Windows 配布物は `.exe` 単体ではなく `clp2cfg-x86_64-pc-windows-msvc.zip` である。
   - `vedantmgoyal9/winget-releaser` の既定 `installers-regex`（`\.(exe|msi|msix|appx)(bundle){0,1}$`）では `.zip` が一致しないため、採用する場合は `installers-regex: 'x86_64-pc-windows-msvc\.zip$'` の指定が必須となる。
3. **`clp2cfg-cli.exe` の同梱方針**
   - `v0.2.0` 以降のリリース ZIP には `clp2cfg.exe` と `clp2cfg-cli.exe` の両方が含まれているが、`0.1.0` マニフェストの `NestedInstallerFiles` には `clp2cfg.exe` のみ記載されている。
   - `wingetcreate update` や `komac update` は既存マニフェストの `NestedInstallerFiles` を引き継ぐため、`#464302` マージ後の初回バージョン更新時に `NestedInstallerFiles` / `Commands` へ `clp2cfg-cli.exe` を追加し（あわせて `1.28.0` と `PrivacyUrl` を反映し、ルート `README.md` の注記を更新する）、以後の自動更新で同構造を引き継ぐ。
4. **自動更新ツールの選定と PR 本文方針**
   - **`vedantmgoyal9/winget-releaser`（内部で `komac` を実行）**: フォーク同期や複数バージョンの保持上限管理に優れ、ワークフロー記述が簡潔。一方で `winget-pkgs` に 1 バージョン以上登録済みでないとエラー終了し、また PR 本文を直接カスタマイズする入力がないため、未署名バイナリや Defender スキャン結果の注記を PR 本文へ載せたい場合は後続ステップで PR 本文を追記する構成が必要。
   - **`wingetcreate update`**: 公式ツールであり `-o` でローカル生成してチェック・加工しやすい一方、フォーク同期や PR 作成処理を自前で組む必要がある。
   - **推奨進め方**: `#464302` マージ直後の初回アップデート（`0.1.0` → 最新安定版、`1.28.0` / `PrivacyUrl` / `clp2cfg-cli` 反映）はローカル生成＋検証のうえ手動 PR で構造を確定させ、その後 Issue `#38` で `winget-releaser`（`installers-regex` 指定＋必要に応じ PR 本文追記）または `komac` ベースのワークフローを `release.yml`（または専用ワークフロー）へ組み込む。
